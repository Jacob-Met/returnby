## Resulting selection and freshness

All saved rows are validated before filtering. Only open orders appear, in
saved order; completed-only data offers no selection. Malformed hidden rows and
duplicate identities refuse the whole collection. Reopening is exclusively the
existing tracker's deliberate action. After Reopen, refresh the enquiry and
explicitly select an order if its prior selection disappeared.

The snapshot retains the complete raw JSON. Before Prepare/Copy/Download,
the original controller rereads and compares that exact value. Hidden-row
changes and whitespace changes therefore stale the snapshot too. Merely
calculating a completion plan is not a storage change. Equality is not a revision
counter: if storage returns to the exact earlier raw string, that snapshot can
be current again. A failed refresh preserves the old prepared message; later use
still depends on a successful current read with exact raw equality.

The four page files retain their original general saved-order/count/empty
wording. The tracker entry help and current guide explain the open-only context.
There is no inferred eligibility, retailer address, refund, message send or
enquiry storage write. Page navigation does not persist unsaved form work.
